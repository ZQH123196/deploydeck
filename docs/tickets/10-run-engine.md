# 10 执行引擎与日志

## 目标

把「取实例、装、启、验」串成一条失败即停的执行链，并留下完整日志。

## 背景

部署配置只声明两个脚本：部署脚本与启动脚本。脚本由引擎按获取方式选择。

## 范围

1. 执行顺序：计划校验 → 取实例（开机复用或克隆）→ 等 SSH 就绪 → 读单价复核预算 → 设定时关机 → 执行脚本 → 健康检查 → 收尾。
2. 脚本选择：克隆路径只跑启动脚本；开机复用路径先跑部署脚本再跑启动脚本。
3. 失败即停。任一步失败，后续不执行。
4. 每步记录：命令、开始与结束时刻、退出码、日志路径、前后截图。
5. 失败处理按 `onDeployFailure`：`keep-container` 标记 `stray`；`destroy-container` 立即销毁。
6. `stray` 与 `failed` 是两个状态。`stray` 表示实例仍存在，需要人处理。

## 不做

不做并行执行。不做步骤重试。重试由人重新发起 `run`。

## 验收

1. 健康检查失败时，按配置分别得到 `stray`（实例仍在）与已销毁（实例消失）两种结果。
2. Run 记录里能读到每一步的命令与退出码。
3. 容器销毁后，本机 run 目录仍能读到全部日志与截图。
