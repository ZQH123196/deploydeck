# AutoDL 控制台选择器与交互清单

实测日期：2026-11-25。实测环境：Windows Chrome 158，视口 1584×1055，经 CDP 驱动。
截图见同目录 `screenshots/`。控制台改版会让本文与 `src/console/selectors.ts` 同时失效。

## 0. 三个通用事实

第一，点击必须用 CDP `Input.dispatchMouseEvent`。JS `.click()` 对 Element Plus 按钮无效。

第二，点击前必须把目标滚进可视区。实例列表比视口宽，「操作」列默认在视口外，
坐标落在视口外时鼠标事件不生效。

第三，页面标签处于后台时（`document.visibilityState === 'hidden'`）Element Plus 的
CSS 过渡不推进，弹层卡在半开状态且 `getBoundingClientRect()` 高度为 0。
判据：不能依赖「动画跑完」来判断可见，要用几何尺寸或 DOM 状态。

### 1.1.1 刷新按钮与「页面不自动刷新」

判据：页面空闲时不会自己取新数据。实测在列表页停留 45 秒，页内
`XMLHttpRequest` / `fetch` 捕获到 0 个请求。加载阶段只发一轮
`/api/v1/instance`、`/api/v1/wallet/balance` 等。

工具栏刷新按钮：

| 项 | 选择器 |
|---|---|
| 刷新按钮 | `.refresh-btn` |
| 图标 | `.el-icon-refresh-right` |

按钮没有文字。判据：**等状态变化的轮询必须先点它再读**，
否则会一直读到同一份旧 DOM，把「状态没变」误判成超时。

实测点它之后会重新发 `GET /api/v1/instance`。

### 1.2 第 0 列结构

```text
td .cell
  div[data-v-3b2e3e03]
    div.region      ← 「西北B区 / 722机」
    div             ← 空
    div[cursor]     ← 实例 ID，如 af9c49bd44-8ee624d7
```

判据：实例 ID 取第 0 列第 3 个 `div` 的文本。该 `div` 没有稳定类名，
只能按结构位置取。实例名取第 4 个 `div`。

### 1.3 状态原文

实测见过：`已关机`、`克隆锁定中`。待实测：`开机中`、`运行中`、`重置中`。
状态单元格里 `.status` 只放状态词，`.gpuTips` 另放补充文字。

### 1.4 行内按钮

| 按钮 | 定位方式 |
|---|---|
| 开机 / 关机 | 第 9 列内、文本等于「开机」或「关机」的 `button` |
| 更多 | 第 9 列内 `.el-dropdown button` |
| 设置定时关机 | 第 6 列内、文本含「设置定时关机」的 `button` |

判据：这些按钮没有语义化类名（只有 `thirteenSize`、`twelveSize` 这类尺寸类），
按文本定位。按文本定位还要限定在第 9 列或第 6 列内，否则会命中别处同名按钮。

**关机也是两步操作（2026-11-25 真机实测）**：点「关机」弹 `.el-message-box`
「确认关机吗？」「实例：<ID>(<名字>)」「按量计费的实例关机后GPU将会释放，再次开机时可能面临空闲GPU不足无法开机，是否继续关机？」，
点「确定」才真正关机。不点则实例继续运行、继续计费。
销毁链（`release.ts`）自己也要关机，同样必须处理这个框。

**开机是两步操作（2026-11-25 真机实测）**：点「开机」不会立即开机，控制台先弹
`.el-message-box` 二次确认，正文「确认开机吗？/ 实例将按￥1.58/时整点扣费」，
页脚「取消」「确定」。点「确定」后才真正发起开机；不点则状态一直停在「已关机」，
外部只看到开机超时。确认框里的金额随规格变化，判据只按「确认开机」这四个字匹配。
消息框按尺寸过滤可见性，取最后一个（后弹出的叠在旧的上方）。


### 1.5 「更多」下拉

截图：`screenshots/more-menu.png`

| 项 | 选择器 |
|---|---|
| 弹层 | `.el-dropdown__popper`，可见判据是 `display !== 'none'` |
| 菜单 | 弹层内 `.el-dropdown-menu li` |
| 每项尺寸 | 高 36px，宽 138px |

菜单项顺序，实测 12 项：
`无卡模式开机`、`更换镜像`、`保存镜像`、`升降配置`、`扩容数据盘`、`缩容数据盘`、
`转包年包月`、`克隆实例新`、`跨实例拷贝数据`、`修改SSH密码`、`重置系统`、`释放实例`。

判据：
- 菜单项文字是「克隆实例新」，不是「克隆实例」。匹配用「包含」而不是「相等」。

**弹层的可见判据（2026-11-26 真机修正）**：点「更多」后弹层在过渡期间
`display: block`、`visibility: visible`，但 `opacity: 0`、高度为 0。

判据：**不要求几何尺寸**。按尺寸判会把刚点开的菜单判成没打开而轮询到超时。
可见 = `display !== 'none'` 且 `visibility !== 'hidden'` 且 `aria-hidden !== 'true'`。
归属由行内 `.el-dropdown` 的 `aria-describedby` 裁决。

**无卡模式开机（2026-11-26 实测）**：菜单第 1 项，点了先弹 `.el-message-box`：
正文「确认无卡模式开机吗？/ 无卡模式配置为:0.5核心CPU，2GB内存，无GPU卡 /
配置费用:￥0.10/时，最低消费￥0.01」，页脚「取消」「确定」。

### 1.6 单元格文本节点

`.cell` 的第一层 div 是内容容器，第二层 div 才放文字。第 0 列（地区、空位、
实例 ID、实例名）、第 2 列（规格）、第 3 列（两个盘）都按 `.cell > div > div` 取，
再按子节点顺序读。带状态图标的列（状态、健康）会先命中图标，那两列不用它。

无名实例的「设置名称」是 button，不是 div。按 div 计数时它被跳过，
实例名仍是第 0 列第 4 个 div（0 基序号 3），此时该 div 文本为空。

### 1.7 付费方式单元格

`.chargeType` 是主文字。余额不足时 `.dateWarn` 嵌在同一层，
`.chargeType` 的 `innerText` 会变成「按量计费 余额不足24小时」。

判据：`.dateWarn` 原文是余额告警；`.chargeType` 原文去掉告警后是付费方式。

### 1.6.1 第 6 列释放时间单元格（2026-11-25 真机实测）

该列有两种主干文字，形状不同，解析必须分开：

| 实例状态 | `.date` 内原文 | 含义 |
|---|---|---|
| 已关机 | `6天04小时31分后释放` | 倒计时：从当前时刻往后推算 |
| 运行中 | `关机15天后释放` | 关机后才开始计 15 天。运行中没有确定的释放时刻 |

两种都含「后释放」。只按「含后释放」判断会把运行中实例送进倒计时解析并报错，
进而让整张列表解析失败——列表里只要有一台实例在跑，全部读取就挂。

设置过定时关机时，同一格还会多出 `.timed-shutdown`：

| 元素 | 原文 |
|---|---|
| `.timed-shutdown > span`（第一个） | `2026-11-25 05:54:00` |
| 同一容器内其他文字 | 「修改」「关闭」两个操作 |

### 1.8 SSH 登录列（2026-11-25 真机实测，与推断不同）

位置：第 7 列（0 基）。实例运行中才有内容；已关机为空。

实测 DOM：

```html
<div>
  <div>登录指令</div>
  <div class="login"><span>ssh******</span><span class="iconfont icon-fuzhi"></span></div>
  <div>密码</div>
  <div class="login"><span>*********</span><span class="iconfont icon-fuzhi"></span></div>
</div>
```

**关键事实：登录指令与密码在 DOM 里都是掩码，明文不在页面文本里。**

| 项 | 实测值 |
|---|---|
| 登录指令显示 | `ssh******`（掩码） |
| 密码显示 | `*********`（掩码） |
| 明文获取方式 | 点 `.icon-fuzhi` 复制图标。控制台建一个无类名 `textarea`，写入明文并选中，再调 `document.execCommand('copy')`，页面弹提示「复制成功」 |
| 明文长度（本次） | 登录指令 46 字符，密码 12 字符 |
| 掩码形态 | 不是固定长度：`ssh` 之后固定 6 个 `*`，密码固定 9 个 `*`。不能从掩码长度反推明文长度 |

判据：

- 不能从单元格文本解析登录指令：那里只有掩码。原推断「按 `ssh -p` 解析单元格文本」不成立。
- 明文只在复制瞬间存在：钩住 `document.execCommand`，在调用前读 `document.activeElement.value`。
- 密码只允许在内存里传，不得写日志、错误消息与截图文件名。
- 行定位用运行时生成并回验的行选择器，不按 `.el-table__row` 计数。

代码：`src/ssh/credentials.ts`、`src/console/selectors.ts` 的 `SSH_LOGIN_CELL`。

## 2. 定时关机对话框

截图：`screenshots/timed-shutdown-dialog.png`

入口：第 6 列「设置定时关机」按钮。

| 项 | 选择器 |
|---|---|
| 对话框 | `.el-dialog[role=dialog]`，标题文字在 `.el-dialog__header span` 内，文本为「定时关机」 |
| 关闭（×） | `.el-dialog__headerbtn` |
| 表单项 | `.el-form-item`，标签 `.el-form-item__label`，内容 `.el-form-item__content` |
| 时间输入框 | `.el-dialog input.el-input__inner`（`el-date-picker`） |
| 页脚按钮 | `.el-dialog__footer button`，文本「取消」「确定」 |

字段与实测取值：

| 字段 | 形式 | 实测 |
|---|---|---|
| 当前服务器时间 | 文本，分钟精度 | `2026-11-25 01:33` |
| 定时关机时间 | `el-date-picker` 输入框 | 空；若已设置过则回填已有时刻 |
| 预计消费 | 文本 | 未填时间时为「选择时间后计算费用」；填后为 `￥ 1.58` |
| 账户余额 | 文本 | `￥ 54.57` |
| 账户代金券 | 文本 | `￥ 0.00` |

### 2.1 填时间与提交

第一，点输入框拿焦点。用 `Input.insertText` 写入文本。

第二，写入后必须让输入框失焦，表单模型才更新。做法是点对话框内部的无害位置
（例如标题文字）。判据：失焦后「预计消费」立即重算；未失焦时校验会报
「请设置定时关机时间」。

第三，禁止点对话框外。遮罩点击会关闭对话框，且不保存。

第四，禁止在输入框里按回车。回车会触发表单动作，实测会直接关闭对话框。

### 2.2 单价反推

实测三次，服务器时间与填入时刻的差分别是 59、60、120 分钟：

| 关机时刻 − 服务器时间 | 预计消费 |
|---|---|
| 59 分钟 | ￥1.55 |
| 60 分钟 | ￥1.58 |
| 120 分钟 | ￥3.16 |

判据：`预计消费 = 单价 × 时长`，单价 = `预计消费 ÷ 时长`，本机实测 vGPU-32GB 为
1.58 元/时。同一台机器的单价与该页「配置费用」显示一致。

判据：预计消费随服务器时间走动而变化。读单价必须同时读服务器时间与当前输入值，
三者取自同一时刻。

### 2.3 设置后的回读（2026-11-25 真机实测）

设置成功后，实例列表第 6 列直接显示已设时刻，**不必重开对话框回读**：

| 状态 | 第 6 列原文 |
|---|---|
| 未设置 | `关机15天后释放` + 「设置定时关机」按钮 |
| 已设置 | `关机15天后释放` + `2026-11-25 05:54:00` + 「修改」「关闭」 |

取消入口是列表里那个「关闭」按钮，不是对话框。原记录「对话框没有取消入口」只说明了
对话框里没有，不代表无法取消。

判据：时刻原文与「修改」「关闭」同处一个容器，只取第一个 `span` 的文字；
解析时也只认开头那段时间。

**定时关机触发后记录不会自动消失**（2026-11-25 实测）：到点关机后，该格仍显示
已过的时刻与「修改」「关闭」，要人工清掉。读到的时刻可能是过去时刻，
调用方必须按时间判断是否仍在生效，不能只看「有没有时刻」。

清除方式：点列表里的「关闭」→ 弹 `.el-message-box`「取消定时关机」「取消 / 确定」→ 点「确定」，
提示「取消成功」，该格回到「设置定时关机」按钮。

deploydeck 把这条做成了 `PricePort.clearTimedShutdown`：有记录才点，没有就什么都不做；
点完按列表回读里 `timedShutdownAt` 变空来判定成功。真机测试的 `afterAll` 会用它把源实例恢复成原样。

### 2.4 实现要点

本节事实来自同一次实测的补充采集，实现见 `src/console/timed-shutdown.ts`。

标题 `span` 没有 `el-dialog__title` 类（克隆实例对话框有），所以第 2 节表格按
结构记 `.el-dialog__header span`。点这个 `span` 也是让时间输入框失焦的实测可行做法。

已关闭的对话框留在 DOM 里，`document.querySelector('.el-dialog')` 可能命中隐藏的旧
对话框。实现先按几何尺寸挑出当前可见的那一个，再生成从 `body` 往下、按「标签加同层
同名序号」拼出的结构选择器，回查一次确认指回同一元素后才用它点击与写入。行定位
沿用开通关机的做法：按实例 ID 找到行，同样生成并回验选择器。

实测遇过一次失败：写入时间后若输入框未真正失焦，日期控件在失焦瞬间把输入框回退成
模型里的旧值，同时保留旧的「预计消费」。两者自洽，反推出来的单价会差一点点。
判据：失焦后必须再读一次输入框，值不等于填入值即报错。

| 2 | 算力型号/显存，如 `vGPU-32GB 32GB` |
| 3 | 空闲GPU，如 `1 / 8` |
| 4 | 每GPU分配，如 `CPU：16核 内存：62GB` |
| 5 | CPU型号 |
| 6 | 硬盘，如 `数据盘：50GB 可扩容：0GB` |
| 7 | 驱动/CUDA |
| 8 | 价格(单卡)：`￥1.58/时`，下一行划掉的原价 `￥1.66/时` |

选择器：表格 `.el-table`，行 `.el-table__row.row-can-click`，单选 `td .el-radio`。

判据：
- 单价在这一列就能直接读到，不需要反推。这是单价的第二个来源。
- 一行必须有可用 GPU 才能选：`空闲GPU` 的值必须大于 0。
- 底部「配置费用 ￥1.58/时」与所选主机一行的价格一致。
- 确认按钮文案是「创建并开机」，不是「确认」。

判据：
- 一行必须有可用 GPU 才能选：`空闲GPU` 的值必须大于 0。
- 多台可用时按单元格 4 的 CPU 核数从多到少挑（原文 `CPU：16核 内存：62GB`）。
  核数读不出的主机排在后面。实现见 `src/console/clone.ts` 的 `pickHostRow`。

判据：创建动作未实测。本 ticket 只走到选主机页，未点「创建并开机」。

### 3.4 实例名（2026-11-25 真机实测，与原推断相反）

**克隆不复制实例名。** 新实例落在列表里 `name` 是空串，第 0 列显示「设置名称」按钮。

| 项 | 实测 |
|---|---|
| 选主机页 | 没有改名入口，URL 参数 `name=` 不决定结果 |
| 克隆结果 | 名字为空，不是源实例名 |
| 改名入口 | 第 0 列的「设置名称」按钮（无名实例）或 `icon-xiugai` 编辑图标（已有名字） |
| 改名交互 | 按钮原位换成 `.el-input.name input`，行作用域选择器是 `.el-input.name input` |
| 提交方式 | **回车不提交**，必须让输入框失焦；成功后弹「修改成功」 |
| 改名上限 | 名字长度受限，超长提交后不生效（未实测具体上限） |

判据：克隆完成后必须显式改名，否则下一次按 `Profile.instanceNamePattern` 找不到这台实例，
会再克隆一台，白烧每日配额与费用。实现见 `src/console/clone.ts` 的 `renameCreatedInstance`。

spec 第 3.5 节说克隆时用 `instanceNamePattern` 作名字，与实测不符：平台不接收这个名字。

### 3.5 克隆产物的磁盘占用要等上报

实测（2026-11-25）：克隆出来的实例刚出现在列表里时，系统盘与数据盘都显示 `0.00%`；
容器起来并上报之后才变成真实占用。数据盘的拷贝在此期间继续推进
（实测同一台实例：`4.15%` → `36.27%` → `55.84%`，源实例 `55.97%`）。

判据：不能拿「刚完成时的磁盘占用」断言盘有没有拷。要轮询到两个盘都不再是 `0.00%`
再判定。反过来说，「状态已经离开克隆锁定中」不等于「数据盘拷完」。
